## 本轮建议

项目页签成为桌面任务面板。点卡片即可在右侧查看任意 Issue，原有对话仍可继续。项目面板够宽时看板和详情并排，较窄时在同一面板内切换，一步回到原来的卡片。用户主动选择「绑定到当前会话」时，Issue 才进入会话的 `issue` 页签。两个入口共用同一套详情和编辑体验。

首版验收以一条流程为准：用户在对话旁打开 Issue，读完讨论，改标题和负责人，移到「In Progress」，然后回到原来的筛选继续处理下一张卡片。除首次登录或补授权外，这条流程应全程留在 DSH。

## 用户与范围

- 主要用户是边聊边处理任务的 DSH Desktop 用户，以及需要连续扫卡、调整项目进度的团队成员。
- 第一版覆盖 Issue 详情和评论、创建 Issue、标题和正文等常用字段、开关 Issue、项目条目状态与常用字段、筛选和返回现场。现有工作区绑定和会话 `issue` 页签是入口。
- 后续扩展沿用同一个详情位置。先补 PR 摘要、Project 草稿、卡片归档和手动排序，再接 GitHub 共享视图及其可写设置。每项按实际权限和公开接口提供对应操作。GitHub 上的共享视图写入应明确表示会影响团队。

## 桌面布局与导航

| 位置 | 内容与行为 |
| --- | --- |
| 对话区 | 继续显示当前会话、输入框和原有页签。右栏详情是非模态页面，用户可以在对话和详情之间来回操作。 |
| 项目页签 | 顶部依次是项目名称、视图切换与筛选。搜索支持标题、编号、仓库和标签。主操作「新建 Issue」与移动、绑定、归档等卡片操作分开。 |
| 宽项目面板 | 看板或列表和选中详情并排。只显示一个详情，点另一张卡片就在同一位置替换。原有 DSH 面板最大化可用。 |
| 窄项目面板 | 在同一个面板中显示详情。顶部常驻「返回看板」和 Issue 编号，返回恢复视图、筛选、横纵滚动和来源卡片焦点。若卡片不再符合筛选，焦点回到列表或对应列标题。 |
| 会话入口 | 保留会话 `issue` 页签。它直接打开该会话绑定的 Issue。若项目面板也打开了同一个 Issue，保存结果同步到两处。 |

宽窄切换以项目面板实际可用宽度为准。看板仍须保住可扫描的列或行，详情须容纳正文与字段操作。原型以约 740 px 的项目面板宽度切换，评审时可调整。界面沿用 DSH 深浅色、系统字体和面板样式。建议正文 14 px、辅助元信息 12 px、标题 18–20 px，布局以 4/8/12/16/24 px 为节奏。泳道颜色辅以文字，所选卡片和键盘焦点各有可见状态。

## 主要操作

### 从卡片打开详情

1. 点击卡片主体或聚焦后按 `Enter`，在 DSH 内打开详情，保持当前会话及其绑定。
2. 立即用卡片已有数据显示编号、标题和状态。正文、评论和其余字段分区加载，打开旧缓存时也能看见当前同步状态。
3. 顶部放编号、Issue 开关状态和返回动作。阅读区先正文、后讨论，字段区放在正文右侧或窄栏正文上方。绑定与「在 GitHub 打开」放入「更多」，仍可通过键盘访问。
4. 关闭详情或返回时恢复来源。已进入详情时，`Esc` 先关闭当前弹层，其次处理正在编辑的表单，再返回看板。打开时将焦点移到详情标题附近的首个控件，返回时恢复来源焦点。

### 编辑 Issue

- 在详情头部点「编辑 Issue」。同一编辑状态里处理标题、正文、负责人、标签和里程碑，只提交改动过的字段。负责人、标签和里程碑按 Issue 实际所属仓库搜索，即使看板横跨多个仓库。
- 表单底部固定「取消」「保存修改」。`⌘↵` / `Ctrl+Enter` 可提交当前编辑表单，保留输入法组合输入。缺少必填信息时将焦点定位到字段旁的提示。关闭、切换卡片或离开时，如果有未保存输入，给出「继续编辑」「放弃修改」。保存中保留内容，阻止重复提交。
- 关闭和重开 Issue 是带明确动词的独立动作。Issue 状态放在标题旁，项目泳道状态放在「项目字段」。如果项目自动化随后移动了卡片，在看板同步显示 GitHub 结果。
- 评论框在讨论末尾，用「发表评论」明确提交。发布失败保留输入，提交结果未知时先重新读取评论，再提示用户决定是否重试。

### 调整卡片与建立新任务

- 看板支持跨列拖动和卡片菜单「移动到…」，两种入口完成同一个操作。详情中的「看板状态」也可以改。同一张卡片写入期间显示进度，新位置立即反馈。失败回到原位置并说明原因，成功后可撤销。撤销前若检测到状态已被其他人改过，提示当前状态并请用户重新选择。
- 「项目字段」展示 GitHub 中实际存在的常用字段，如优先级、迭代和日期。选择单个字段后单独保存，并显示该字段的结果。编辑 Issue 正文不要求重新填写项目字段。
- 「新建 Issue」优先预填当前工作区对应的仓库和当前项目，仓库可选。创建并加入项目应告知两个结果。如果 Issue 已经创建、加入项目失败，保留 Issue 编号，让用户只重试「加入项目」。
- 同列排序放在后续版本，并遵循共享视图的排序规则。在按字段排序的视图里明确显示排序依据。

## 同步、权限与异常

| 状态 | 用户看到的反馈与动作 |
| --- | --- |
| 刚打开或后台刷新 | 有缓存时立即显示；仅在无数据时使用分区骨架。打开面板、窗口回到前台时自动刷新，可见期间定期刷新，仍提供「刷新」。正在编辑的输入保留。 |
| 同字段被别人改动 | 在提交前发现标题或正文等同一字段发生变化时，展示「GitHub 上有新修改」并提供查看最新内容、复制自己的草稿或返回编辑。只改不同字段时，保留对方改动。 |
| 保存失败或超时 | 在按钮或字段旁给出原因，保留草稿并提供重试。请求结果未知时先读取 GitHub 最新状态，尤其避免重复创建 Issue、重复发评论。 |
| 可查看、无法编辑 | 正常浏览。按项目或仓库显示可行动原因，比如「项目写入未启用」或「此仓库没有 Issue 编辑权限」。项目权限和仓库权限可能不同。 |
| 尚未登录或授权不足 | 面板内显示 GitHub 连接状态及下一步。「检查连接」在授权后原地复查。复用本地 `gh` 账号，首次授权和补授权由 GitHub CLI 完成。 |
| 保存后卡片不符合筛选 | 详情保持打开到用户主动返回，并显示「此 Issue 已不符合当前筛选」。保留原筛选，可一键清除。 |
| 条目删除、转移或不可见 | 在详情显示最新状态和「返回看板」。有未提交内容时允许复制草稿。 |

建议沿用显式启用写入的入口，首版通过该入口开放 GitHub 写操作。GitHub 作为数据来源，保存在 GitHub 得到确认后才显示成功，详情、看板和会话副标题应更新为相同结果。首版日常读写用现有 `gh` 和按需刷新即可。 [Projects API](https://docs.github.com/en/issues/planning-and-tracking-with-projects/automating-your-project/using-the-api-to-manage-projects) · [Issues API](https://docs.github.com/en/rest/issues)

## 可观察的验收场景

| 场景 | 通过条件 |
| --- | --- |
| 对话旁已有未发送文字，点另一张 Issue 卡 | 详情在 DSH 内打开。对话、输入与已绑定 Issue 保持原样。 |
| 列表带搜索和两个筛选，打开卡片后缩窄再返回 | 宽窄布局可切换，返回一步完成，恢复筛选、滚动和焦点。 |
| 只用键盘查看、编辑、改状态 | 可打开卡片、保存或取消，并通过菜单改状态。焦点一直可见，`Esc` 按当前交互层级返回。 |
| 保存当前会话绑定的 Issue 新标题 | GitHub 返回成功后，详情、看板标题和会话副标题显示新值。 |
| 填写正文后断网，或遇到并发修改 | 草稿仍在，可看清失败或冲突原因，有原地恢复路径。 |
| GitHub 拒绝拖动写入，或移动使卡片离开筛选 | 失败回到原位并显示原因。成功却离开筛选时，已打开的详情继续可见。 |
| 仓库能改 Issue，项目只读 | 仍可保存合法的 Issue 字段。看板状态说明项目缺少写权限。 |
| Issue 创建成功而加项目失败 | 可查看已建 Issue，并补做「加入项目」。 |

## 本轮评审与签字项

1. **详情位置与绑定**。建议详情留在项目右栏，宽时并排、窄时返回，点击卡片保持会话绑定。备选是点击后切到中间 `issue` 页签。
2. **首版范围**。建议首版覆盖查看与编辑 Issue、评论、创建、移动卡片和常用项目字段。备选是把创建与额外项目字段放入下一版，优先交付读、改、评、移。
3. **写入与外部更新**。建议保留显式启用写入，切回窗口和可见期间自动刷新。备选是有权限就开放写入，或将团队实时推送列为首版要求。

## Open Questions And Risks

- 上面的三个选择均为本轮建议，待用户确认。桌面内完成高频操作与交互友好是明确的需求。
- 实机验证须覆盖 DSH 窄侧栏、侧栏最大化、会话切换、快捷键冲突、跨仓库项目及多窗口刷新。
- 共享视图的公开写入参数支持名称、布局、筛选、可见字段，不包含视图分组与排序参数。组织项目的卡片事件可以订阅 webhook，个人项目的卡片更新按需拉取。 [视图更新 API](https://docs.github.com/en/graphql/reference/projects#updateprojectv2viewinput) · [卡片事件范围](https://docs.github.com/en/webhooks/webhook-events-and-payloads#projects_v2_item)

## 实现约束

沿用工作区到项目、会话到 Issue 的模型。一张卡片可以在多个项目出现，Issue 字段以仓库和 Issue 编号标识，项目字段属于具体项目条目。保留 GitHub 原字段名和选项，常用操作使用 DSH 语言设置。首版延续本机 `gh` 授权和 DSH 内面板，GitHub 链接用作显式入口。
